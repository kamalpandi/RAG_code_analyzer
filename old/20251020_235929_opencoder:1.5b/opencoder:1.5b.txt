Directory: 2 - dependency inversion
The purpose of this directory is to demonstrate the concept of Dependency Inversion in object-oriented programming. 

Dependency inversion is a principle where high-level modules should not depend on low-level modules; instead, they should depend on abstractions. This means that the interaction between different parts of the program should be abstracted away, and instead, the abstraction should provide the required functionality.

The contents of this directory work together in the following way:

1. `dependency-inversion-before.py`: This file is a simple example of Dependency Inversion before it's introduced into object-oriented programming. It demonstrates how high-level modules (modules that contain business logic) depend on abstractions, not on low-level modules (modules that perform actual computations). The ElectricPowerSwitch class in this example does not know anything about the details of how electricity is switched; instead, it relies on an abstraction called `Electricity` to switch power.

2. `dependency-inversion-after.py`: This file introduces Dependency Inversion into object-oriented programming. It makes dependencies explicit by making the `Electricity` class abstract (an interface that any implementation must provide) and not hiding them behind a concrete implementation like a concrete class `ElectricPowerSwitch`. The ElectricPowerSwitch class in this example now depends on an interface called `IElectricity`, which allows it to switch power without knowing anything about how the actual switching is done. This makes the code more modular, easier to change or add new types of electricity (like solar panels), and more flexible.

In summary, Dependency Inversion is a principle that promotes high-level modules interacting with low-level modules; these interactions should be abstracted away, so high-level modules only know about what they need to do, not how it does it. This results in cleaner, more modular code.
